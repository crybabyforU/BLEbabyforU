################################################################################
# 1. WHAD BUTTERFLY - nRF52840 USB DONGLE
################################################################################

TAG:      [DONGLE]
WHAT:     Nordic nRF52840 USB dongle running WHAD "ButteRFly" firmware. Acts as a
          BLE sniffer / injector / central over a serial protocol.
USB IDs:  c0ff:eeee (normal), 1915:521f (bootloader/DFU)
PORT:     /dev/ttyACM0 (fallback /dev/ttyACM1), addressed as uart0/uart1 in WHAD
FLASH:    ButteRFly firmware (already installed); ZEPHYR/ is an alternative
          HCI firmware image if you want the dongle to behave as a normal adapter.
NEEDS:    uucp group membership, ModemManager disabled, pyserial can open the port.
USED BY:
  2_send_packet.py
  4_inject_raw.py
  5_scan_then_inject.py
  6_scan_inject_final.py
  7_connect_lifecycle.py
  8_trigger_sweep.py
  10_prepare_rootcause.py
  11_max_fidelity.py
  12_ab_diagnose.py
  13_death_autopsy.py
  14_mtu_responder.py
  15_manual_att.py
  oooooooooooo.py
  own_packet_full.py
  sweyntooth_crash.py
  tools/whadbro/dos.py
  tools/whadbro/sooooooooo.py
  (verified by check.sh)

# 2. HOST BLUETOOTH ADAPTER - BLE
################################################################################

TAG:      [HOST]
WHAT:     The computer's built-in Bluetooth chip or a USB BLE adapter, driven by
          BlueZ. Used by all bleak-based scripts. No special firmware needed.
CHECK:    hciconfig / bluetoothctl list should show an adapter (hci0).

  getting-all-details-of-ble.py

################################################################################
# 4. NORDIC nRF52840 + SWEYNTOOTH DRIVER FIRMWARE
################################################################################

TAG:      [NRF52-ST]
WHAT:     Nordic nRF52840 USB dongle flashed with the SweynTooth driver firmware.
          It sends/receives raw BLE Link Layer packets over serial.
FLASH:    nrfutil dfu usb-serial -p /dev/ttyACM0 -pkg nRF52_driver_firmware.zip
          (hold the small reset button while plugging in to enter DFU mode)
PORT:     /dev/ttyACM0 on Linux (COMx on Windows)
USED BY:
  All 13 tools/sweyntooth_bluetooth_low_energy_attacks/*.py
  tools/SbleedyGonzales/modules/sweyntooth/*.py
  sbleedy -fhw nRF52840 (flashes sweyntooth_nRF52840_firmware.zip)

# 5. TI CC1352 / CC26x2 LAUNCHPAD - SNIFFLE SNIFFER
################################################################################

TAG:      [SNIFFLE]
WHAT:     TI CC1352/CC26x2 Launchpad running Sniffle firmware. Independent BLE
          capture path used to verify that injected packets really went on-air.

  LAUNCHXL-CC26X2R1, LP-CC2652RB, LAUNCHXL-CC1352R1, LAUNCHXL-CC1352P,
  LP-CC2652R7, LP-CC1352P7, LP-CC2651P3, LP-EM-CC1354P10, EC CatSniffer V3
FLASH:    make load in tools/Sniffle/fw (uses the on-board XDS110 debugger)
USED BY:

################################################################################
# 10. TARGET DEVICES
################################################################################

TAG:      [TARGET]
WHAT:     The device under test. Can be any BLE peripheral, classic device,
          development board or phone that you own or are authorized to test.

Default BLE target used in the lab scripts:
  C0:00:00:41:73:AC   (random static address, device name "MDT2410161")

Other targets referenced in the scripts:
  00:1F:FF:C1:63:9F
  80:E1:27:4D:A8:3F

WARNING: Never run DoS or exploit modules against devices you do not own or do
not have explicit written authorization to test.
